#Resultado de aprendizaje

Identifica sistemas de planificación de recursos empresariales y de gestión de relaciones con clientes (ERP-CRM) reconociendo sus características y verificando la configuración del sistema informático.

#Criterios de evaluación

a) Se han reconocido los diferentes sistemas ERP-CRM que existen en el mercado.
	En la unidad anterior vimos diferentes sistemas ERP-CRM, lo que me permitió elegir qué tipo de sistema quería desarrollar. En esta unidad hemos empezado a ver cómo se construyen estos sistemas, trabajando con módulos como ventas, recursos humanos, facturación y compras. Esto me dio una idea de cómo organizar los diferentes módulos de mi CRM.

b) Se han identificado los diferentes tipos de licencia de los sistemas ERP-CRM.
	Como vimos en la unidad anterior, existen diferentes tipos de licencias como GPL, Apache o propietaria. En mi caso sigo manteniendo la elección de una licencia propietaria para mi CRM, ya que mi intención es que en un futuro pueda ofrecer el acceso a la plataforma mediante una suscripción.

c) Se han comparado sistemas ERP-CRM en función de sus características y requisitos.
	Hemos visto cómo se organizan los sistemas ERP-CRM y cómo podemos separar los diferentes módulos del núcleo principal de la aplicación. Esto me permitió tener una idea más clara de cómo 	organizar mi 	propio CRM, separando las diferentes funcionalidades para que el proyecto sea más fácil de mantener y ampliar en un futuro.


d) Se ha identificado el sistema operativo adecuado a cada sistema ERP- CRM.
	Hemos trabajado con Linux, concretamente Ubuntu, utilizando Apache y PHP para ejecutar nuestro sistema. También hemos visto la arquitectura cliente-servidor, separando la parte del cliente con HTML, CSS y JavaScript de la parte del servidor con PHP y la base de datos. En mi caso mantendré esta arquitectura, utilizando Linux como servidor y permitiendo que los usuarios accedan desde cualquier navegador web.

e) Se ha identificado el sistema gestor de datos adecuado a cada sistema ERP-CRM.
	Hemos trabajado principalmente con SQLite para crear las bases de datos de nuestro proyecto DarkOrange. Vimos que SQLite es una buena opción para crear prototipos, ya que es sencillo de utilizar y no necesita un servidor de bases de datos independiente. En mi caso para el CRM sigo eligiendo MySQL, ya que quiero desarrollar el proyecto utilizando PHP y Laravel.

f) Se han verificado las configuraciones del sistema operativo y del gestor de datos para garantizar la funcionalidad del ERP-CRM.
	Hemos visto cómo configurar Apache y PHP en Ubuntu para que nuestro sistema funcione correctamente. También vimos cómo activar los errores de PHP desde el archivo php.ini, consultar los registros de Apache e instalar la extensión php-sqlite3 para poder conectar nuestra aplicación con la base de datos SQLite.

g) Se han documentado las operaciones realizadas.
	Hemos visto cómo documentar nuestro proyecto utilizando archivos Markdown, donde podemos guardar la información sobre la estructura del proyecto, las bases de datos y el código utilizado. También hemos utilizado una herramienta que genera automáticamente la documentación de nuestro proyecto, lo que nos permite tener un registro de las diferentes versiones y los cambios realizados.

h) Se han documentado las incidencias producidas durante el proceso.
	Hemos visto cómo detectar posibles errores durante el desarrollo de nuestro sistema ERP-CRM y cómo documentar los procedimientos para solucionarlos. Por ejemplo, en el archivo debug.md vimos cómo activar los errores de PHP, consultar los logs de Apache e instalar la extensión de SQLite en caso de que no esté disponible. Esto nos permite tener una referencia para solucionar problemas similares en un futuro.
